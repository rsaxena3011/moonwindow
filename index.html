Data & honesty

Flat-horizon model. Horizons gives Sun/Earth elevation above a smooth sphere. Real crater rims and ridges block the Sun and Earth at low elevations. No terrain shadowing is used. Earth visibility is geometric line-of-sight only — no relay satellites, link budgets, or landing-safety modelling. This is an educational screening prototype, not flight-planning software.

All astronomical values were computed by NASA JPL's Horizons system (DE441 ephemeris) from live API queries made during the build (2026-11-13) and stored as data files in the repository — no AI generated any data value. Times are UT; Horizons uses the last known leap second as a constant for future intervals. Metrics are hourly estimates, not exact rise/set times. The generation script (generate_data.py) and the raw Horizons responses (data/raw/) are in the repository so any value can be traced and regenerated.

Use of Super Intelligence (AI): This project answers NASA's official Space Apps Challenge 2026 problem statement, "Lunar Landing Site Navigator". The challenge idea is the organisers'; no AI was used to come up with the idea. AI-assisted tools helped draft and debug code and explore interface design; the final approach was selected, reviewed and tested by the author, who is responsible for the submitted work. All astronomical values shown were computed by NASA JPL Horizons (DE441) — no AI generated any data value. No AI-generated images are used. Moon texture: none (schematic map). This is an educational screening prototype, not flight-planning software: it estimates geometric sunlight and Earth line-of-sight, not power output, link budgets, or landing safety.
